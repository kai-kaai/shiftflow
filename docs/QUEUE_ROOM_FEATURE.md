## 1. เป้าหมาย

สร้างหน้า **「ห้องจัดคิว」** สำหรับวางแผนลำดับคิวพนักงาน **ทั้งเดือน** แยกตาม **ทีมสี**  
รูปแบบคล้าย `Q.numbers` (หลายคอลัมน์ = หลายวันทำงาน)

ตอน **สร้างการจัดเวรใหม่**:
- ถ้าวัน/กะนั้นมีคิวในห้องจัดคิวของทีม → **ใช้คิวคอลัมน์นั้นเป็น suggestion เติมใน textarea**
- ถ้าไม่มี → **fallback เดิม**: เวรล่าสุดของทีมเดียวกัน + หมุนซ้าย 1
- User **แก้ชื่อ/ลำดับใน modal ได้เต็มที่** ก่อนกดสร้าง — นั่นคือ **final decision**
- การแก้ตอนสร้างเวร **ไม่ update กลับ** ไปที่ห้องจัดคิว

### หลักการสำคัญ: Suggestion vs Final

| ชั้น | ที่อยู่ | บทบาท |
|---|---|---|
| **Suggestion** | ห้องจัดคิว | แผ่นวางแผนทั้งเดือน — ใช้เติมคิวแนะนำเท่านั้น |
| **Final decision** | Modal สร้างการจัดเวรใหม่ (textarea ลำดับคิว) | User แก้ได้ทันที; ค่าที่กดสร้าง = คิวจริงของเวรนั้น |
| **One-way** | สร้างเวร → ห้องจัดคิว | **ไม่เขียนกลับ** ห้องจัดคิวไม่เปลี่ยนเพราะสร้าง/แก้เวร |

## 4. ขอบเขต

### In scope

- เมนู **ห้องจัดคิว** ใต้ 「หน้าหลัก / ตารางเวร」 (sidebar + mobile)
- เลือก **เดือน/ปี** + **ทีมสี**
- ตารางหลายคอลัมน์ = **ทุกวันทำงานของทีมนั้นในเดือนที่เลือก**
  - วันทำงานคำนวณจาก `getTeamForDate` / `TEAM_SCHEDULE` (รอบ 8 วัน)
  - 1 วันอาจมีได้ 2 กะ (เช้า + บ่ายดึก) ถ้าทีมนั้นเข้าทั้งสอง — **แต่ละกะ = 1 คอลัมน์**
- ช่องใส่คิว **คอลัมน์แรก (วันทำงานแรกของเดือน)** โดย user
- ปุ่ม **Run Que** → เติมคิวคอลัมน์ที่เหลือด้วย rotate ซ้าย 1 ต่อคอลัมน์
- บันทึกแผนคิวทั้งเดือนของทีมลง DB
- ตอนสร้างเวรใหม่: ดึงคิวจากคอลัมน์ที่ match วันที่+กะ ถ้ามี
- fallback เดิมเมื่อไม่มีข้อมูลในห้องจัดคิว

### Out of scope (รอบหลัง ถ้าไม่ระบุเพิ่ม)

- ลากเรียง (drag-and-drop)
- รหัสผ่านเฉพาะห้องจัดคิว
- แก้ supervisor ต่อคอลัมน์แบบเต็ม (ดู optional)
- ส่งออก Excel / import จาก `.numbers`

## 6. User flow

### 6.1 จัดคิวทั้งเดือนในห้องจัดคิว

```
1. เปิดเมนู 「ห้องจัดคิว」
2. เลือกเดือน (เช่น กรกฎาคม 2026) + เลือกแท็บทีม (ม่วง/เขียว/เทา)
3. ระบบวาดตารางว่าง: คอลัมน์ = วันทำงานทั้งหมดของทีมในเดือนนั้น
4. User กรอกลำดับคิวในคอลัมน์แรก (วันทำงานวันแรก)
   - ช่องใส่: textarea หรือช่องชื่อย่อทีละแถว
5. กดปุ่ม 「Run Que」
   - ตรวจว่าคอลัมน์แรกไม่ว่าง
   - col[i+1] = rotateLeft1(col[i])  ทำซ้ำจนครบทุกคอลัมน์
6. (ถ้าต้องการ) แก้คอลัมน์ใดคอลัมน์หนึ่งด้วยมือหลัง Run
7. กด 「บันทึก」 → เก็บลง DB
```

### 6.2 สร้างการจัดเวรใหม่ (หน้าหลัก) — final decision อยู่ที่นี่

```
เปิด modal สร้างเวร → เลือกวันที่ + กะ
  teamId = getTeamForDate(date, shift_type)
  หาคอลัมน์ในห้องจัดคิว: teamId + เดือนของ date + (date, shift_type)

  ถ้าเจอคิวและไม่ว่าง:
    เติม textarea จากคอลัมน์นั้น (suggestion — ใช้ตรงๆ ไม่หมุนซ้ำ)
    แสดง: "แนะนำจากห้องจัดคิว · ทีมม่วง · 1 Jul A+N (แก้ไขได้)"
  ถ้าไม่เจอ:
    logic เดิม: เวรล่าสุดทีมเดียวกัน + หมุนซ้าย 1
    แสดง: "แนะนำจากเวรล่าสุด · ทีมม่วง (แก้ไขได้)"

  User แก้ชื่อ/ลำดับใน textarea ได้เต็มที่ (บางคนหรือทั้งคิว)
  → กดสร้าง → บันทึกเฉพาะ shifts.queue ของเวรนั้น
  → ไม่ PUT/อัปเดต team_month_queues
```

**สำคัญ:** การแก้ไขใน modal เป็น final decision ของ user  
ห้องจัดคิวยังคงเป็นแผ่น suggestion เดิม ไม่ถูก overwrite

## 7. ปุ่ม Run Que — รายละเอียด

| รายการ | รายละเอียด |
|---|---|
| ชื่อปุ่ม | **Run Que** (หรือ 「รันคิว」) |
| Input | คิวคอลัมน์แรก (วันทำงานแรกของเดือนของทีมนั้น) |
| Algorithm | `next = rotateLeft1(prev)` ทีละคอลัมน์ ตามลำดับวันทำงาน |
| `rotateLeft1` | คนแรก → ท้ายคิว (เหมือน `getSuggestedQueue` เดิม) |
| หลังรัน | เขียนทับคอลัมน์ที่ 2..N (คอลัมน์แรกคงที่) |
| ยืนยันก่อนทับ | ถ้าคอลัมน์หลังมีข้อมูลอยู่แล้ว → confirm 「จะเขียนทับคิวที่เหลือทั้งเดือนไหม?」 |
| ยังไม่บันทึก DB | Run Que ทำในหน้าจอก่อน แล้ว user กด **บันทึก** แยก (เสนอ) |

```
function rotateLeft1(queue):
  if empty: return []
  return queue[1..] + [queue[0]]

function runQue(columns):
  // columns[0].queue ต้องมีค่าแล้ว
  for i in 1 .. columns.length-1:
    columns[i].queue = rotateLeft1(columns[i-1].queue)
```

## 8. โมเดลข้อมูล (เสนอ)

### ตาราง: `team_month_queues`

เก็บแผนคิว **ทั้งเดือนต่อทีม** เป็น JSON ชุดเดียว (อ่าน/เขียนง่าย)

| คอลัมน์ | ชนิด | ความหมาย |
|---|---|---|
| `id` | INTEGER PK | |
| `team_id` | TEXT NOT NULL | `purple` / `green` / `gray` |
| `year_month` | TEXT NOT NULL | เช่น `2026-07` |
| `columns_json` | TEXT NOT NULL | JSON รายการคอลัมน์ (ด้านล่าง) |
| `updated_at` | TEXT | ISO timestamp |

**UNIQUE** `(team_id, year_month)`

### รูปแบบ `columns_json`

```json
[
  {
    "date": "2026-07-01",
    "shift_type": "A+N",
    "queue": ["SG", "GK", "WF", "SN", "WE", "TT", "PB", "TY", "JZ", "TH", "BA", "PR", "BP"],
    "supervisor": ""
  },
  {
    "date": "2026-07-07",
    "shift_type": "M8/A14",
    "queue": ["GK", "WF", "SN", "WE", "TT", "PB", "TY", "JZ", "TH", "BA", "PR", "BP", "SG"],
    "supervisor": ""
  }
]
```

> ตอนโหลดหน้า: merge โครงคอลัมน์จากปฏิทินทีม (source of truth ของ “มีกี่วันทำงาน”) กับข้อมูลที่เซฟไว้  
> ถ้าปฏิทินเปลี่ยน (เพิ่มทีม/แก้ anchor) คอลัมน์ใหม่ว่าง / คอลัมน์ที่หายไปตัดทิ้งตอน save รอบถัดไป

### API เสนอ

| Method | Path | หน้าที่ |
|---|---|---|
| `GET` | `/api/team-month-queues?team_id=&year_month=` | โหลดแผน 1 ทีม 1 เดือน |
| `GET` | `/api/team-month-queues?year_month=` | โหลดทุกทีมในเดือน (optional) |
| `PUT` | `/api/team-month-queues` | บันทึก body: `{ team_id, year_month, columns: [...] }` |
| `DELETE` | `/api/team-month-queues?team_id=&year_month=` | ล้างแผนเดือนนั้นของทีม |

Lookup ตอนสร้างเวร (frontend หรือ endpoint ย่อย):

```
GET /api/team-month-queues/lookup?date=2026-07-01&shift_type=A+N
→ { found: true, team_id, queue: [...] }
→ { found: false }
```

(หรือ frontend โหลดแผนเดือนไว้แล้วค้นเองก็ได้)

## 10. Logic หลัก (Pseudo)

### 10.1 สร้างรายการคอลัมน์ทั้งเดือน

```
function buildWorkColumns(teamId, year, month):
  cols = []
  for day in daysInMonth(year, month):
    dateStr = format(year, month, day)
    for type in ["M8/A14", "A+N"]:
      if getTeamForDate(dateStr, type) === teamId:
        cols.push({ date: dateStr, shift_type: type, queue: [] })
  return cols  // เรียงวันที่ + เช้าก่อนบ่าย
```

### 10.2 Run Que

```
function runQue(columns):
  base = columns[0].queue  // ต้องไม่ว่าง
  prev = base
  for i = 1 .. n-1:
    prev = rotateLeft1(prev)
    columns[i].queue = prev
```

### 10.3 Suggest ตอนสร้างเวร (เติม textarea เท่านั้น — ไม่ lock)

```
function getSuggestedQueue(date, shiftType):
  teamId = getTeamForDate(date, shiftType)
  plan = loadTeamMonthQueue(teamId, yearMonthOf(date))
  col = plan.columns.find(c => c.date === date && c.shift_type === shiftType)

  if col && col.queue.length > 0:
    return col.queue   // suggestion ตรงๆ

  // fallback เดิม
  lastShift = mostRecentSameTeam(teamId)
  if lastShift: return rotateLeft1(lastShift.queue)
  return roster.slice(0, 13)
```

## 14. Acceptance criteria

- [ ] เมนู **ห้องจัดคิว** ใต้หน้าหลัก (desktop + mobile)
- [ ] เลือกเดือน + ทีมสี → เห็นคอลัมน์ครบทุกวันทำงานของทีมในเดือนนั้น
- [ ] ใส่คิวคอลัมน์แรกได้
- [ ] กด **Run Que** แล้วคอลัมน์ที่เหลือถูกเติมด้วยหมุนซ้าย 1 ทีละคอลัมน์
- [ ] บันทึกแล้วรีเฟรชหน้าแล้วยังอยู่
- [ ] ชื่อย่อใหม่ตอนบันทึกห้องจัดคิว → เข้า roster อัตโนมัติ
- [ ] สร้างเวรใหม่วันที่ตรงคอลัมน์ที่มีคิว → textarea ถูกเติมจากห้องจัดคิว (suggestion)
- [ ] แก้ชื่อ/ลำดับใน textarea ตอนสร้างเวรได้ — ค่าที่บันทึกคือคิวของเวรนั้นเท่านั้น
- [ ] หลังสร้างเวร (แม้แก้คิว) ห้องจัดคิว**ไม่**ถูกเปลี่ยน
- [ ] วันที่/ทีมที่ไม่มีคิวในห้อง → fallback เวรล่าสุด + หมุน 1
- [ ] ไม่พัง flow ห้องจัดเวร / hourly log / ทีม rotation เดิม
- [ ] อยู่บน branch `q` เท่านั้น

## 15. ความเสี่ยง

| ความเสี่ยง | แนวทาง |
|---|---|
| คอลัมน์ทั้งเดือนเยอะ เลื่อนยากบนมือถือ | sticky header + scroll แนวนอน + คอลัมน์แรกกว้างชัด |
| ปฏิทินทีมเปลี่ยนหลังเซฟแผน | merge โครงคอลัมน์ใหม่กับข้อมูลเก่าตอนโหลด |
| User แก้คอลัมน์กลางหลัง Run Que | อนุญาต; ถ้ากด Run Que อีกครั้งจะทับจากคอลัมน์แรก (confirm) |
| สับสน suggestion vs คิวจริงของเวร | ข้อความใน modal: “แนะนำจาก… (แก้ไขได้)” + ไม่เขียนกลับห้องจัดคิว |
| วันทำงานวันแรกของเดือนยังไม่ชัด (ทีมยังไม่เริ่ม) | ใช้ “คอลัมน์แรกที่ทีมมีเวรในเดือนนั้น” ไม่ใช่วันที่ 1 ของปฏิทินเสมอ |
| Supervisor ใน header Q.numbers | MVP เว้นว่างหรือแสดงจาก shift ที่มีอยู่แล้ว; ขยายทีหลัง |

## 16. สรุปสั้นๆ (ฉบับอัปเดต — ปิดแผน)

> **ห้องจัดคิว** = ตารางหลายคอลัมน์ครบเดือน ต่อทีมสี (คล้าย `Q.numbers`)  
> ใส่คิววันทำงานแรก → **Run Que** หมุนซ้าย 1 เติมวันทำงานที่เหลือ → บันทึกแผนเดือน  
> ชื่อใหม่ในห้องจัดคิว → เพิ่ม roster อัตโนมัติ  
> ตอนสร้างเวร = ดึง suggestion จากคอลัมน์วัน/กะ (หรือ fallback เวรล่าสุด)  
> **User แก้ใน modal ได้เต็มที่ = final decision** — **ไม่** เขียนกลับห้องจัดคิว  
> แผนครบแล้ว พร้อม implement บน branch `q` เมื่อสั่ง
